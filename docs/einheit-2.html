Einheit 2: Daten einlesen & aufräumen

In dieser Einheit geht es vom einzelnen Vektor zur ganzen Tabelle — und von der Datei zu sauberen Daten:

  1. Listen und Faktoren — zwei weitere Datenstrukturen, die in Tabellen ständig vorkommen
  2. Data Frames — die zentrale Struktur für tabellarische Daten in R
  3. Daten einlesen — CSV & Co. in R laden
  4. Unordentliche Daten aufräumen — Kopfzeilen, falsche Datentypen und Spaltennamen in Ordnung bringen
  5. Ergebnisse speichern — CSV, RDS und RData

In dieser Einheit arbeiten wir nur mit Basis-R, es werden keine Zusatzpakete gebraucht.

Teil 1: Listen und Faktoren

Listen

Vektoren und Matrizen enthalten nur einen Datentyp. Eine Liste kann dagegen beliebige Objekte unterschiedlichen Typs und unterschiedlicher Länge sammeln:

wien_info <- list(stadt           = "Wien",
                  einwohner       = 2000000,
                  bezirke         = c("Innere Stadt", "Leopoldstadt", "Landstraße"),
                  temperatur_juli = c(TMax = 26.0, TMin = 16.4))
str(wien_info)
List of 4
 $ stadt          : chr "Wien"
 $ einwohner      : num 2e+06
 $ bezirke        : chr [1:3] "Innere Stadt" "Leopoldstadt" "Landstraße"
 $ temperatur_juli: Named num [1:2] 26 16.4
  ..- attr(*, "names")= chr [1:2] "TMax" "TMin"

Ein einzelnes Element holt man mit $ oder doppelten eckigen Klammern [[ ]]:

wien_info$stadt
[1] "Wien"
wien_info[["bezirke"]]
[1] "Innere Stadt" "Leopoldstadt" "Landstraße"

Listen begegnen dir vor allem indirekt: Viele Funktionen geben ihr Ergebnis als Liste zurück, und ein Data Frame (Teil 2) ist eine Liste gleich langer Vektoren.

Faktoren

Ein Faktor ist der Datentyp für kategoriale Variablen — Werte aus einer begrenzten Menge an Kategorien (z. B. Land, Bewertungsstufe). Zwei Arten:

  • nominal — ohne Reihenfolge, z. B. "Katze", "Hund", "Pferd"
  • ordinal — mit Reihenfolge, z. B. "niedrig" < "mittel" < "hoch"

Mit factor() wird ein Text-Vektor zu einem Faktor; die vorkommenden Werte werden zu Levels. summary() zählt die Häufigkeit pro Level:

tiere <- factor(c("h", "k", "h", "p", "k", "h"))
tiere
[1] h k h p k h
Levels: h k p
summary(tiere)
h k p 
3 2 1

Levels umbenennen

Daten enthalten oft Kürzel statt lesbarer Bezeichnungen. R sortiert die Levels alphabetisch ("h", "k", "p") — in genau dieser Reihenfolge lassen sie sich mit levels() umbenennen:

levels(tiere) <- c("Hund", "Katze", "Pferd")
tiere
[1] Hund  Katze Hund  Pferd Katze Hund 
Levels: Hund Katze Pferd

Nominal vs. ordinal

Bei einem nominalen Faktor ergibt ein Größenvergleich keinen Sinn — R gibt eine Warnung und NA zurück:

tiere[1] > tiere[2]
Warning in Ops.factor(tiere[1], tiere[2]): '>' ist nicht sinnvoll für Faktoren
[1] NA

Für einen geordneten Faktor gibt man ordered = TRUE und die levels in der richtigen Reihenfolge an — dann funktionieren Vergleiche:

tempo <- factor(c("mittel", "langsam", "schnell", "mittel"),
                ordered = TRUE, levels = c("langsam", "mittel", "schnell"))
tempo
[1] mittel  langsam schnell mittel 
Levels: langsam < mittel < schnell
tempo[1] > tempo[2]   # ist "mittel" schneller als "langsam"?
[1] TRUE

Übung

  1. Lege eine Liste kurs an mit den Elementen titel ("R-Einführung"), teilnehmende (eine Zahl) und themen (ein Vektor mit mindestens drei Themen). Gib das zweite Thema aus (Tipp: erst das Element holen, dann [ ]).
  2. Kursbewertungen liegen als Text vor: bewertungen <- c("gut", "sehr gut", "mittel", "gut", "schlecht", "sehr gut", "gut")
    • Mache daraus einen geordneten Faktor von "schlecht" bis "sehr gut".
    • Zähle mit table(), wie oft jede Bewertung vorkommt. In welcher Reihenfolge stehen die Levels — und warum?
    • Wie viele Bewertungen sind besser als "mittel"? (Tipp: sum())

Teil 2: Data Frames

Was ist ein Data Frame?

In einer Matrix haben alle Elemente denselben Datentyp. Reale Datensätze mischen aber fast immer Typen: ein Name (character), ein Alter (numeric), eine Ja/Nein-Angabe (logical) …

Ein Data Frame speichert genau das: Variablen als Spalten, Beobachtungen als Zeilen — jede Spalte mit ihrem eigenen Datentyp. Das entspricht einer Tabelle, wie man sie aus Excel kennt.

R bringt einige Datensätze mit, z. B. mtcars (Kenndaten von 32 Automodellen, 1974):

Erste Einblicke in einen Datensatz

  • head() / tail() — die ersten bzw. letzten Zeilen
  • str() — Anzahl Zeilen und Spalten, Datentypen, Beispielwerte
  • summary() — Kennzahlen pro Spalte (Minimum, Mittelwert, Maximum …)
  • nrow() / ncol() — Anzahl Zeilen bzw. Spalten

Einen eigenen Data Frame erstellen

Wir bauen einen Data Frame mit den acht Planeten unseres Sonnensystems: Typ, Durchmesser (relativ zur Erde), Rotationsdauer (in Erdtagen; negativ = dreht sich rückwärts) und ob der Planet Ringe hat:

name        <- c("Merkur", "Venus", "Erde", "Mars", "Jupiter", "Saturn", "Uranus", "Neptun")
typ         <- c("Gesteinsplanet", "Gesteinsplanet", "Gesteinsplanet", "Gesteinsplanet",
                 "Gasriese", "Gasriese", "Eisriese", "Eisriese")
durchmesser <- c(0.382, 0.949, 1, 0.532, 11.209, 9.449, 4.007, 3.883)
rotation    <- c(58.64, -243.02, 1, 1.03, 0.41, 0.43, -0.72, 0.67)
hat_ringe   <- c(FALSE, FALSE, FALSE, FALSE, TRUE, TRUE, TRUE, TRUE)

Kategorien ansehen und zählen: unique(), table()

unique() zeigt, welche verschiedenen Werte in einer Spalte vorkommen, table() zählt sie:

unique(planeten$typ)
[1] "Gesteinsplanet" "Gasriese"       "Eisriese"      
table(planeten$typ)

      Eisriese       Gasriese Gesteinsplanet 
             2              2              4

Soll die Spalte als Kategorie behandelt werden, macht man sie zum Faktor (Teil 1) — z. B. um eine sinnvolle Reihenfolge festzulegen statt der alphabetischen:

planeten$typ <- factor(planeten$typ,
                       levels = c("Gesteinsplanet", "Gasriese", "Eisriese"))
table(planeten$typ)

Gesteinsplanet       Gasriese       Eisriese 
             4              2              2

Zeilen filtern

Ein logischer Vektor in der Zeilenposition wählt die Zeilen aus, bei denen TRUE steht:

planeten[planeten$hat_ringe, ]           # nur Planeten mit Ringen
     name      typ durchmesser rotation hat_ringe
5 Jupiter Gasriese      11.209     0.41      TRUE
6  Saturn Gasriese       9.449     0.43      TRUE
7  Uranus Eisriese       4.007    -0.72      TRUE
8  Neptun Eisriese       3.883     0.67      TRUE
planeten[planeten$durchmesser < 1, ]     # nur Planeten kleiner als die Erde
    name            typ durchmesser rotation hat_ringe
1 Merkur Gesteinsplanet       0.382    58.64     FALSE
2  Venus Gesteinsplanet       0.949  -243.02     FALSE
4   Mars Gesteinsplanet       0.532     1.03     FALSE

subset() ist die kürzere Schreibweise — man kann die Spaltennamen direkt verwenden:

subset(planeten, durchmesser < 1)
    name            typ durchmesser rotation hat_ringe
1 Merkur Gesteinsplanet       0.382    58.64     FALSE
2  Venus Gesteinsplanet       0.949  -243.02     FALSE
4   Mars Gesteinsplanet       0.532     1.03     FALSE

Sortieren mit order()

sort() sortiert einen Vektor. Um einen Data Frame zu sortieren, braucht man order(): Es liefert nicht die Werte, sondern die Positionen in sortierter Reihenfolge.

preise <- c(100, 10, 1000)
sort(preise)    # die sortierten Werte
[1]   10  100 1000
order(preise)   # 10 steht an Position 2, 100 an Position 1, 1000 an Position 3
[1] 2 1 3

Diese Positionen als Zeilenindex sortieren den ganzen Data Frame:

Teil 3: Daten einlesen

In der Praxis liegen Daten fast immer als Datei vor — meistens als CSV (comma-separated values): eine Textdatei mit einer Beobachtung pro Zeile und einem Trennzeichen zwischen den Spalten.

R sucht Dateien relativ zum Arbeitsverzeichnis. Wird das Projekt über r-einfuehrung.Rproj geöffnet, ist das der Projektordner (siehe Einheit 0):

getwd()
[1] "C:/Users/mironova/OneDrive - TU Wien/Dokumente/Teaching/R_course/RIntroduction/_website"

CSV einlesen mit read.csv()

read.csv() liest eine CSV-Datei und gibt einen Data Frame zurück:

mitarbeitende <- read.csv("data/raw/mitarbeitende.csv")
teams         <- read.csv("data/raw/teams.csv")

Deutsche CSV-Dateien: read.csv2()

read.csv() erwartet , als Trennzeichen und . als Dezimalzeichen. Excel im deutschsprachigen Raum speichert CSV dagegen oft mit ; als Trennzeichen und , als Dezimalzeichen. Dafür gibt es read.csv2():

read.csv2("data/raw/datei.csv")                       # ; als Trenner, , als Dezimalzeichen
read.csv("data/raw/datei.csv", sep = ";", dec = ",")  # gleichwertig, explizit

Weitere nützliche Argumente:

  • skip = 3 — die ersten 3 Zeilen überspringen (z. B. Info-Zeilen über der Tabelle)
  • header = FALSE — wenn die erste Zeile keine Spaltennamen enthält
  • na.strings = c("", "NA", "-") — welche Einträge als fehlend (NA) gelten sollen
  • fileEncoding = "UTF-8" (oder "latin1") — bei falsch dargestellten Umlauten

Andere Dateiformate

Format Funktion Paket

CSV, schneller & strenger read_csv("datei.csv") readr
R-eigenes Format (.rds) readRDS("datei.rds") Basis-R

Teil 4: Daten aufräumen

Echte Dateien sind selten sofort verwendbar: oben stehen Info-Zeilen, Zahlen kommen als Text an, Spaltennamen enthalten Leerzeichen. Die Datei data/raw/bezirke_roh.csv ist so ein Fall — Semikolon-getrennt, mit vier Info-Zeilen vor der eigentlichen Kopfzeile.

Die Rohdatei ansehen

Wir lesen zunächst ohne Kopfzeile ein (header = FALSE), um zu sehen, was in der Datei steht. Weil in jeder Spalte auch Text vorkommt, sind alle Spalten character:

Kopfzeile setzen und Info-Zeilen entfernen

bezirke <- roh[-(1:5), ]               # Zeilen 1–5 entfernen
rownames(bezirke) <- NULL              # Zeilennummerierung zurücksetzen

Spaltennamen säubern: gsub() und tolower()

Rohdaten halten sich selten an die Namensregeln aus Einheit 1. gsub(muster, ersatz, text) ist Suchen-und-Ersetzen: Wir tauschen Leerzeichen gegen Unterstriche — dann funktioniert $ ohne Backticks. tolower() macht alles klein, damit die Namen snake_case sind:

names(bezirke)
[1] "Bezirk Nummer"       "Bezirk Name"         "Haushalte"          
[4] "Mittleres Einkommen"
names(bezirke) <- tolower(gsub(" ", "_", names(bezirke)))
names(bezirke)
[1] "bezirk_nummer"       "bezirk_name"         "haushalte"          
[4] "mittleres_einkommen"

Datentypen reparieren: as.numeric() & lapply()

Die Zahlenspalten sind noch Text (chr). Für eine Spalte ginge das mit bezirke$haushalte <- as.numeric(bezirke$haushalte). Für mehrere Spalten auf einmal nimmt man lapply(): Es wendet eine Funktion auf jede Spalte an und gibt die Ergebnisse als Liste zurück, die wir direkt in die Spalten zurückschreiben:

zahl_spalten <- c("bezirk_nummer", "haushalte", "mittleres_einkommen")
bezirke[zahl_spalten] <- lapply(bezirke[zahl_spalten], as.numeric)

Der kurze Weg: skip = 4

Der Weg oben zeigt, was beim Aufräumen passiert. In der Praxis erledigt skip = 4 Kopfzeile und Datentypen in einem Schritt: Die ersten vier Zeilen werden übersprungen, Zeile 5 wird Kopfzeile, und R erkennt die Zahlenspalten selbst. Leerzeichen in Spaltennamen ersetzt R dabei durch Punkte:

str(read.csv2("data/raw/bezirke_roh.csv", skip = 4))

Text zusammensetzen und zerlegen: paste(), substr(), trimws()

paste() verbindet Textstücke mit einem Leerzeichen, paste0() ohne Trennzeichen:

paste("AT", "13", "01")     # "AT 13 01"
[1] "AT 13 01"
paste0("AT", "13", "01")    # "AT1301"
[1] "AT1301"
bezirke$label <- paste0(bezirke$bezirk_nummer, ". ", bezirke$bezirk_name)
head(bezirke$label)
[1] "1. Innere Stadt" "2. Leopoldstadt" "3. Landstrasse"  "4. Wieden"      
[5] "5. Margareten"   "6. Mariahilf"

substr(text, start, stop) schneidet Zeichen nach Position heraus — nützlich, um kombinierte Codes zu trennen:

codes <- c("AT130", "AT127", "AT111")
substr(codes, 1, 2)   # Land
[1] "AT" "AT" "AT"
substr(codes, 3, 5)   # Regionscode
[1] "130" "127" "111"

trimws() entfernt überflüssige Leerzeichen am Anfang und Ende — ein häufiges Problem bei Daten aus Excel:

trimws("   Wien   ")
[1] "Wien"

Zahlen in Kategorien einteilen: cut()

cut() teilt eine Zahlenspalte anhand von Grenzen (breaks) in Kategorien ein und liefert einen Faktor zurück (siehe Teil 1, Faktoren):

bezirke$groesse <- cut(bezirke$haushalte,
                       breaks = c(0, 15000, 40000, Inf),
                       labels = c("klein", "mittel", "groß"))

Teil 5: Ergebnisse speichern

Bereinigte Daten speichert man nach data/processed/ — data/raw/ bleibt unverändert.

Als CSV: write.csv() und write.csv2()

Gut zum Weitergeben, auch an Excel. row.names = FALSE verhindert eine zusätzliche Spalte mit Zeilennummern:

write.csv(bezirke, "data/processed/bezirke_clean.csv", row.names = FALSE)    # , und .
write.csv2(bezirke, "data/processed/bezirke_clean.csv", row.names = FALSE)   # ; und ,

write.csv2() schreibt mit ; und Dezimalkomma — so öffnet ein deutschsprachiges Excel die Datei direkt richtig. Nachteil von CSV: Faktor-Stufen gehen verloren, und beim erneuten Einlesen muss R die Datentypen neu erkennen.

Im R-Format: saveRDS() und save()

# RDS — ein Objekt, behält Datentypen und Faktor-Stufen exakt
saveRDS(bezirke, "data/processed/bezirke.rds")
bezirke <- readRDS("data/processed/bezirke.rds")

# RData — mehrere Objekte in einer Datei
save(bezirke, roh, file = "data/processed/bezirke.RData")
load("data/processed/bezirke.RData")   # holt sie unter denselben Namen zurück

Faustregel: CSV zum Weitergeben, RDS als Zwischenstand für die eigene Weiterarbeit in R.
